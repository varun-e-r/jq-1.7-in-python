Build a drop-in replacement for the jq 1.7.1 command-line JSON processor in pure Python.

The program is `/app/jq`, run as `python3 /app/jq [options] FILTER [args...]` with its input on stdin. For the same arguments and the same stdin it must write the same bytes to stdout as jq 1.7.1 and exit with the same status. Nothing written to stderr is compared, so error wording matters wherever it reaches stdout, for example through `try ... catch .`, and nowhere else. Use Python 3.12 and its standard library only. `/app/jq` is the entry point and may import any modules you place under `/app`. The starter `/app/jq` prints nothing and exits 99; replace it. There is no jq binary, no libjq and no network in this environment, and none of them exist where your code is graded.

What is graded is jq 1.7.1 as it actually behaves, including the places where that differs from the manual or from other versions. That covers the whole filter language: paths, iteration, slices and optional access; array, object and string construction with interpolation; every operator on every type; `//`, `and`, `or`; `if`/`elif`, `try`/`catch`, `reduce`, `foreach`, `label`/`break`; function definitions with filter and `$` parameters, recursion and closures; destructuring with `?//`; path expressions and the assignment operators `=`, `|=`, `+=`, `-=`, `*=`, `/=`, `%=`, `//=`; `$__loc__`; the `@` formats; the regular expression builtins (`test`, `match`, `capture`, `scan`, `split/2`, `splits`, `sub`, `gsub`); the math functions; and the other builtins jq 1.7.1 ships, whether jq implements them in C or in its builtin jq library. It covers jq's numbers: a number literal from the program or from the input keeps its original decimal text until arithmetic touches it, and computed doubles print in jq's own format. It covers jq's runtime and parse error messages wherever they become output, compile errors, malformed input part way through a stream, and the exit status in every one of those situations.

The graded options are `-n`, `-r`, `-j`, `-a`, `-c`, `-s`, `-R`, `-e`, `-S`, `--tab`, `--indent n`, `--arg`, `--argjson`, `--args` and `--jsonargs`, including combined short flags such as `-nr` and options placed after the filter. Input always comes from stdin; no case passes input file names.

Never graded: the date and time builtins (`now`, `mktime`, `gmtime`, `localtime`, `strftime`, `strptime`, `todate`, `fromdate` and the rest of that family), `env` and `$ENV`, `input_line_number`, `builtins`, modules (`import`, `include`, `-L`), `--stream`, `--seq`, `-f`, `--slurpfile`, `--rawfile` and colour output. Regular expressions in graded cases use Oniguruma's Perl syntax as jq does, restricted to literals, character classes, `^` and `$`, greedy and lazy quantifiers, plain and named groups, alternation and the escapes `\d`, `\w`, `\s`, with the flags `g`, `i`, `x` and `n`.

`/app/examples/cases.jsonl` holds 1197 recorded jq 1.7.1 runs. Each line gives the `args` list, the `stdin` text, the expected `stdout`, the expected `exit_code` and a `category`. `python3 /app/run_examples.py` scores your program against them exactly as the grader scores its own cases; `--show N`, `--category` and `--id` help when debugging. The grader uses 2417 different runs in the same nine categories (`core`, `types`, `numbers`, `strings`, `formats`, `control`, `errors`, `cli`, `fuzz`). They come from the same generators with different inputs, and about a third of the program templates behind them never appear in the examples, so the examples are a sample of the surface, not the test.

A graded case passes when stdout matches byte for byte and the exit status matches; each case has 10 seconds. The score is the mean over the nine categories of the fraction of that category's cases passed, so partial work earns partial credit. The grader copies `/app` and runs `/app/jq` as an unprivileged user from an empty working directory. Keep everything the program needs under `/app` as source text: binary files, compiled extensions and archives are rejected, and `/app` must stay under 8 MB.

You have 20 hours. The sandbox is offline. Keep `/app` in a working state as you go, because whatever is there when time runs out is what gets graded.
